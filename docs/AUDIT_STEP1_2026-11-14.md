# 实验审计链第一步（2026-11-14）

## 决策与范围

- 接受随机 epoch 和稳定 vault ID 的方向。新实验 vault 创建时生成 128 位随机 `vault_id`；旧 vault 在首次使用 M1 链时于同一事务内补入。普通明文合成库也有独立身份，只用于测试，不代表其数据受加密保护。
- `0020_audit_chain.sql` 添加身份与审计链表。实验链只覆盖 M1 的 `audit()` 调用，并继续写原 `audit_events`；其他业务服务、现有备份 `audit.log`、已发生的历史事件不在本链中。历史事件没有被追溯认证。
- 当前 epoch 首次使用时随机生成；**恢复后自动分叉、`restored_from`、外部接受 epoch 尚未实现**。这需要可信外部水位，不能仅在旧快照内部自行证明回退已获授权。
- 虚构明文库迁入实验 vault 时，若源库已有审计身份，会先校验本地链，再把同一身份写入目标 vault；缺失部分链表或检测到损坏会拒绝迁移。新 vault 密钥轮换及同机备份恢复测试保留 vault ID。
- 接受 M1 审计追加失败时回滚相关 M1 写入。导入、建议、决定与整条 M1 流使用保存点，物化沿用原保存点；不替调用者提交事务。锁竞争 `SQLITE_BUSY` 作为错误传给调用者，不伪装为成功；当前没有自动重试。重试应在调用方回滚整个事务后限次重试，避免重放外部副作用。
- 检查点签名密钥尚未生成。建议采用系统保护的日常密钥并配独立离线恢复材料，避免仅靠单机凭据管理器导致换机失去验证能力；具体算法、恢复/轮换和信任根需在 checkpoint 阶段独立评审。不能把私钥明文放仓库或将备份口令直接复用。

## 编码与本地检查

- 规范化：UTF-8、Unicode NFC、键排序、无空格 JSON；拒绝 NFC 后重复键、非字符串键、浮点数、NaN、非支持类型及超出有符号 64 位整数；显式 null 与缺字段不同。保留事件固定字段与版本 `1`，不复制 M1 metadata 或内容。
- `SHA256(b"jarvis.audit.chain.v1\\x00" || prev_hash的32字节 || 规范化事件字节)`，创世前驱为 32 字节零；事件含 vault ID、epoch、序号和类型。追加之前复核整条本地链；这使写入累计成本可能为 O(n²)，当前只适合虚构小数据实验，分段、增量校验及性能基线未实现。
- 校验可报 `CHAIN_BROKEN`、`CHAIN_GAP` 或 `LOCAL_CHAIN_CONSISTENT_UNANCHORED`。**没有外部水位时，尾部删除和修改后重算整条链会被识别为本地自洽，不能保证发现；验收测试明确验证这个反例。** 本地链不阻止能修改数据库与代码的攻击者伪造历史。
- SQLite 合成默认连接改为内存临时存储以支持嵌套保存点并减少临时磁盘文件；不代表系统页面文件或进程内存得到保护。

## 尚未完成

checkpoint 与 outbox 仅有本地实验原型，见[阶段记录](AUDIT_CHECKPOINT_STAGE_2026-11-14.md)；独立可信水位、新鲜度、epoch 接受与分段归档都未实现，也未连接 R2。备份 sink 的条件创建已实现并通过假客户端测试；R2 桶锁、权限和实际服务行为未验证。现有明文 `audit.log` 尚在使用，不能声称备份审计已受完整性保护。G1、独立安全评审和异机恢复仍未通过，禁止真实资料。

## 第二步：备份快照绑定（本机虚构实验）

- 备份 metadata（表数、schema 版本、key ID）和 M1 审计链头均从加密快照读取；有链时 `(version, vault_id, epoch, seq, head)` 纳入 manifest HMAC。快照内链损坏或审计表不完整时拒绝创建备份。未初始化审计身份或没有链的备份不添加链头。
- 恢复时先验证 HMAC、密文摘要和数据库完整性，再比较快照链和清单；存在头且一致时返回 `SNAPSHOT_INTERNALLY_CONSISTENT`，旧归档或无链快照返回 `LEGACY_UNANCHORED`。两者都不证明最新或具备可信外部水位。
- 专项测试覆盖旧备份、快照后源库发生变化、HMAC 有效但快照链头不一致被拒，以及恢复整份旧归档只能报告内部一致。外部检查点缺失时，旧归档回滚无法区分有意恢复与恶意回滚。

## 第三步：条件创建（仅本地模拟）

- 默认上传使用 `If-None-Match: *` 的单次 `PutObject`，不再通过 HEAD 判断；前置条件失败或并发条件冲突映射为拒绝，权限错误继续报告。显式 `overwrite=True` 仍保留原调用语义，不具有只追加保证。
- 假 S3 客户端验证双并发同名写最多成功一次、条件冲突和认证异常；未调用 R2。条件创建不阻止删除后重建，也不能代替桶锁、权限隔离、独立 checkpoint 或防回滚机制。
