# Jarvis 底层优先实施方案

> **历史文档（2026-11-08 起）：** 本页是旧方案的记录，阶段状态与验收以 [JARVIS_V2_EXECUTION.md](JARVIS_V2_EXECUTION.md) 为准；保留它是为了追溯，不表示当前计划。


**状态：** 已确认先做底层；前端暂停新增功能  
**更新：** 2026-11-06

## 目标

把现有 HUD 作为后续可替换的展示壳，先建立可独立验证的本地核心。当前优先 Jarvis：待办、合成邮件工作流、收集与知识的基础能力；陪伴模式保留通道与现有数据结构，暂停扩展，待用户重新梳理需求。暂不接真实账号、云模型、同步服务或对外写操作。

## 当前资产与缺口

- preview.html：v0.3 模拟 HUD，数据在浏览器 localStorage，不是后端客户端。
- app.py：冻结的 Streamlit 试验版，不作为新服务入口。
- requirements.txt：FastAPI、Pydantic、Uvicorn；项目内虚拟环境已安装用于合成数据验证。
- backend：已有 SQLite 迁移、领域服务和 API 路由；核心冒烟和部分 HTTP 路由合成数据验证通过；新领域服务尚未全部接入 API。
- 账户/同步/加密、邮件/X 连接器：设计阶段；不得把原型假数据状态当作真实能力。

## 底层边界

HUD（后续 API 客户端）→ FastAPI 本地 API → 应用服务/用例 → 助手上下文与权限策略 → 仓储接口 → SQLite。模型和外部连接器以后经独立适配器接入。HTTP 路由不直接拼 SQL；权限策略先于记忆查询；不引入微服务、向量数据库或自动 Agent 工具循环。

## 初版数据域

1. 助手档案、隔离会话与消息。
2. 记忆分区、候选/已确认记忆、来源、跨助手授权。
3. 可审阅的续聊卡，仅接受后可恢复上下文。
4. 本地待办及来源关联。
5. 为后续审批预留动作提案与审计事件，初期不执行外部动作。

数据库初版见 backend/migrations/0001_core.sql。它是本地开发 schema，不代表已实现加密存储。

## 数据和隐私门槛

- 初期只用合成数据；不能把邮件、聊天、密钥或真实账户内容导入这个未加密数据库。
- 保存真实个人会话/记忆前，必须先实现并审查设备端静态加密、密钥存放、备份与删除语义。
- 多设备同步前完成端到端密钥生命周期与墓碑/冲突协议；不能先上传明文。
- 云模型接入前有模型适配层、逐次发送说明/取消、最小化上下文和明确接收方。
- 权限在服务层执行；隐藏 UI 按钮不构成权限控制。

## 实施里程碑

### B0 — 数据合同与本地骨架（已编码）
已完成：核心 schema、FastAPI 应用入口、SQLite 迁移 runner、健康检查。待完成：配置收口、仓储接口、稳定错误格式与 API 的 owner/assistant 上下文。验收：空数据库可初始化；迁移版本可识别；不依赖前端即可调用领域/API 层。

### B1 — 本地领域服务（核心冒烟验证通过）
已编码：记忆网关与助手隔离、独立会话/消息服务、草稿续聊卡和接受恢复、待办 CRUD/状态流转/来源校验、恢复删除、只读分享与撤权、元数据审计。核心服务已在 Python 3.13 与合成数据上通过冒烟验证。验收：陪伴不能查工作记忆、Jarvis 不能查陪伴记忆；跨助手仅明确授权后可访问；禁记/删除内容不再召回；未接受快照不进入新会话；待办能关联来源。

### B2 — 本地 API（核心待办 HTTP 验证通过，其余覆盖待扩展）
版本化 /api/v1 已覆盖健康检查、助手、会话/消息、记忆、续聊卡和待办。API 只接领域用例，不暴露任意 SQL 或任意文件路径。语法、数据库迁移与领域服务通过合成数据验证；本机 HTTP 验证覆盖健康、认证、请求来源、待办生命周期与助手隔离，尚非全部路由和生产认证的验收。

### B3 — 安全与个人数据准备（设计和合成模式门禁完成，加密未实现）
已写 DATA_SECURITY_DESIGN.md，数据库连接需显式启用 synthetic 模式；门禁不等于加密。真实私人数据进入前仍需实现并验证静态加密、OS 密钥库、备份恢复、导出/删除与本地服务访问保护，并做威胁审查。

### B4 — HUD 接入与增量 B
Jarvis 底层稳定后，再让 HUD 通过 API 替换浏览器本地状态；随后完成待办与 Gmail 只读/草稿/逐项审批。陪伴功能保留通道并暂缓；每个连接器独立授权与验收。
