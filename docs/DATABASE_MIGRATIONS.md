# 本地数据库迁移可靠性 J6

**状态：** 已实现并通过合成数据验证；加密存储尚未实现。

迁移器在打开数据库后取得写入锁，在同一个事务内检查已应用版本、运行所有待执行迁移并写入版本记录。SQL 执行或版本检查失败时回滚本批改动；已有已提交版本保留。并发启动按数据库写入锁串行化，后到的进程重新检查已应用版本。

迁移文件必须从 0001 起连续、编号唯一，已记录的版本与文件名必须一致。为维持事务边界，迁移不允许自行执行 BEGIN、COMMIT、ROLLBACK、SAVEPOINT、VACUUM、ATTACH 或其他会破坏当前事务的语句；当前仅允许 foreign_keys=ON 这一 PRAGMA。SQLite 外键检查在连接建立时启用。

验证脚本 backend/verification/verify_migrations.py 使用临时数据库检查全新迁移失败回滚、已有数据库升级失败保留旧版、修复后重试与重复运行、并发启动、禁止事务控制和历史名称不匹配。现有 Jarvis 合成工作流回归也已通过。

新库记录每个迁移原始字节的 SHA-256 校验和；重启前校验所有已应用文件，内容或名称不符时拒绝继续。散列检查用于发现意外改动，不提供签名或对抗同时篡改代码和数据库的攻击。运行和校验使用同一份内存快照，避免两次读取间内容改变。

旧的合成数据库没有校验和，默认拒绝静默建立基线。维护者可在确认数据库仅含合成数据、核对并备份迁移文件及数据库后，显式调用 `apply_migrations(path, allow_legacy_baseline=True)` 一次；这只记录当前文件，不能证明过去实际执行的文件内容，基线和升级在同一事务中，失败回滚。不要对真实资料使用该路径；当前不支持真实资料。

验证已覆盖同名文件内容改动、旧库默认拒绝、显式基线、升级失败回滚以及基线后正常重启。断电、磁盘故障和损坏数据库的恢复仍未验证；不能将本阶段当作真实资料可用的保障。
