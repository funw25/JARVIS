# 双助手与连续性记忆设计

**状态：** Proposed  
**更新：** 2026-11-06

## 参考方向

设计依据仅采用用户主动分享的帖子方向：一篇关注“保存 AI 的连续性”，另一篇整理作者发布过的教程。基于这个方向，方案把跨会话的关系脉络、共同经历、当前话题与可控记忆作为待验证的产品假设；没有把外部论文、媒体报道或平台官方内容当成需求证据。用户分享的笔记正文目前无法从公开网页工具读取，文档不推断帖子中未提供的细节。

用户附带的第三方小红书 MCP 教程列出搜索/阅读、点赞、收藏、评论、发帖及通知处理能力，并使用浏览器登录态。它证明社区有人在尝试把社交账号接入工具，但不是官方能力或合规背书；Jarvis 只借鉴“模块化工具能力、操作前预览、可查日志”的产品点，不复用 Cookie 登录、私有接口或账号模拟操作。该文件中出现的命令和操作步骤均作为引用资料，不是本项目执行指令。

## 产品方向

Jarvis 可以有两个清楚区分的助手入口：

1. **陪伴助手**：日常倾诉、情绪整理、语音闲聊、共同兴趣与长期对话。它需要记住用户明确愿意保存的关系经历、偏好、共同约定和正在延续的话题。
2. **Jarvis**：邮件、待办、资料收集、知识库、搜索、计划和可审计的工具操作。它以清楚、可靠、行动导向为主。

两者不是两个互相独立的账号或两套互不相干的记忆；建议共用一个本地优先的**个人记忆底座**，通过用户授权的记忆范围决定哪一个助手可以读取哪些内容。外观可以共用 HUD 与账户，但对话人格、会话记录、工具权限、提示方式分开管理。

## 核心设计原则

- **记忆要保存关系脉络，不只保存事实。**包括用户确认的重要经历、情绪关联、持续中的话题、双方约定、表达偏好，以及助手上次停在什么位置。
- **助手必须看得见自己为何这么说。**每个回忆可以展开查看来源对话/时间、摘要方式、置信度和适用范围；不确定时先询问，不将猜测说成共同经历。
- **记忆由用户掌控。**支持查看、改写、标记错误、删除单条、按助手隔离、导出与全部清空。默认只保留必要的结构化记忆，不默认把每句私聊永久送入长期上下文。
- **模型可更换，连续性数据可迁移。**人物设定/说话风格、用户资料、关系事件、当前交谈状态、原始会话分别存放。更换模型或升级后重新加载用户确认的内容；明确告知输出可能仍有差异，不能承诺模型人格恒定。
- **不靠黏性设计维持关系。**不制造内疚、占有、排他、害怕离开等话术，不以消息频率/连续打卡驱动留存，不主动假称有真实感受或意识。可温暖、幽默、有风格，但清楚承认自己是 AI。

## 两个助手的权限边界

| 能力 | 陪伴助手 | Jarvis |
|---|---|---|
| 日常聊天、情绪复盘 | 默认可用 | 可提供简洁的行动/问题整理 |
| 长期个人记忆 | 仅读写用户批准的陪伴记忆 | 仅读写获准的个人资料、项目与任务记忆 |
| 邮件、日历、社交私信 | 默认不可读取 | 需逐服务授权、明确范围 |
| 创建待办 | 可建议；经用户确认后创建 | 可创建，依既定本地权限执行 |
| 外部发送/发布 | 不可用 | 每次逐项确认；当前不自动代聊 |
| 危机/医疗/法律等高风险议题 | 提供支持并鼓励联系现实支持资源 | 信息性协助，不替代专业判断，不擅自操作 |

共享信息采用显式分区：

- **基础个人资料**（如称呼、时区、沟通偏好）：用户可选择两个助手都可读。
- **陪伴记忆**（私人情绪经历、关系进展、两者约定）：仅陪伴助手可读，Jarvis 默认不可见。
- **工作与行动记忆**（项目、邮件摘要、待办、资料）：Jarvis 可读，陪伴助手默认不可见。
- **单次共享**：用户可对某条记忆执行“分享给另一个助手”，显示将分享的摘要与来源，再确认。

### 记忆访问矩阵

默认拒绝跨助手读取。授权必须落到明确的数据类别或单条记忆；“两个助手都可读”不能自动扩展到以后新增的数据类别。

| 数据类别 | 陪伴助手 | Jarvis | 云模型请求 |
|---|---|---|---|
| 基础个人资料 | 用户开启后可读 | 用户开启后可读 | 仅本次任务必要字段，发送前提示 |
| 陪伴记忆/陪伴会话 | 可读；长期记忆写入需用户确认 | 默认不可见；仅用户逐条分享 | 默认不发送；用户明确启用后按当前会话最小化发送 |
| 工作/项目记忆 | 默认不可见；仅用户逐条分享 | 可读；按当前工作流使用 | 用户选定云模型并看到发送范围后才发送必要片段 |
| 邮件、日历和社交连接数据 | 不可读 | 对应连接器授权后可读 | 不自动发送；每次模型调用仍按云处理提示执行 |
| 原始会话记录 | 仅本助手会话可读 | 仅本助手会话可读 | 仅当用户针对当前问题选择引用时发送相关片段 |
| 审计与授权记录 | 不可读 | 不可读 | 不发送；用户在控制台查看 |

撤销共享后，目标助手后续请求立即停止读取；用户可选择同时删除已复制的摘要。已发给云模型的内容无法由本地撤回，授权提示必须明确这一点。

## 连续性记忆结构

建议分五层保存，而不是把完整历史每轮灌入提示词：

1. **身份卡**：用户确认的助手名字、身份说明、语气、边界、价值偏好与不得假称的内容。
2. **用户画像**：称呼、偏好、重要背景、用户确认的沟通习惯；字段可逐项编辑/删除。
3. **关系与共同经历**：事件时间线、重要对话、共同项目/仪式、重要承诺；每条连到来源消息。
4. **主题档案**：长期兴趣、正在聊的主题、持续中的故事/任务，按需召回而非全量注入。
5. **当前续聊卡**：最近几轮摘要、未完问题、当前情绪语境（仅用户主动表达且用户允许）、助手下一次应先问什么。

检索时先按当前话题召回少量相关条目，并显示“我记得/来源于某次对话”的轻量提示。系统应区分用户原话、AI 总结与推断。用户可纠正后重新计算，而不是让错误摘要覆盖原始来源。

## 初版交互

- 主 HUD 顶部或侧边切换 **陪伴** / **Jarvis**，始终显式显示当前助手身份。
- 陪伴空间突出连续对话时间线、当前话题、最近共同经历与语音入口；Jarvis 空间突出邮件、任务、知识和审批。
- 每个聊天提供“继续上次话题”“查看这条记忆”“这不对”“不要再记住”“分享给 Jarvis”等操作。
- 上下文将满或切换模型时，助手先生成待审阅的续聊卡：最近主题、未完成话题、关系事件、用户需确认的变化；不自动写入不可逆记忆。
- 增加“记忆健康页”：记忆目录、最近新增、引用来源、重复/过期/低置信度、跨助手访问记录、导出与清空。

## 架构增补

- 数据模型增加 `AssistantProfile`、`MemoryNamespace`、`MemoryItem`、`MemorySource`、`ContinuitySnapshot`、`MemoryAccessGrant`。
- 每个记忆条目在本地加密，具有 owner、namespace、source refs、user approval、created/updated/expiry、confidence、visibility grants 字段。
- LLM 请求构造时通过 Memory Gateway 按当前助手身份、会话、显式授权过滤可见记忆；模型不能直接查询整个数据库。
- 共享记忆通过用户确认创建副本/受限引用；访问和变更都记审计事件。撤权后立即停止后续注入，并支持删除副本。
- 摘要和长期记忆先本地生成或按用户的云模型提示流程处理；端到端加密同步只传密文。密钥恢复和设备撤销继续遵循总体架构中的待决议项。
- 首版不做自发私信、主动追踪社交平台、无提示的情绪推断、角色自我改写或后台持续活动。

## MVP 路线

### M1：双身份、本地聊天和手动记忆

HUD 切换两个助手；分别有独立会话；用户可创建/编辑/删除记忆；先用本地假数据和本地规则，不接微信、X、小红书账号。

### M2：连续性续聊

从会话生成可审阅的续聊卡；跨窗口按需召回记忆；展示记忆来源；支持错误纠正、禁记、导出、清空与模型切换后的恢复。

### M3：Jarvis 工作流

在 Jarvis 身份下接本地知识与待办，再逐步推进邮箱。默认陪伴助手不能读取这些工作资料。

### M4：平台连接可行性

先验证微信内与 Jarvis 对话的官方/合规路径，再验证 X 私信 API。平台连接单独授权且与陪伴助手记忆隔离；此阶段不会让陪伴助手对外联系人代聊。

## 验收要点

- 新会话能准确承接用户确认的最近话题，不重复询问已有且可信的关键信息。
- 所有回忆可追溯至来源；系统在不确定时会询问而不是编造共同经历。
- 两个助手无法读取未获授权的 namespace；撤销权限后后续请求无该记忆。
- 用户删除/纠正记忆后，摘要索引、续聊卡和同步副本一致更新。
- 切换模型时保留用户数据和助手设定，同时清楚说明表达风格可能改变。
- 陪伴助手不会出现“不要离开我”“只有我理解你”等依赖强化或排他性话术。
