# Jarvis 接口合同草案（本地优先）

状态：设计草案。2026-11-07 已接入部分本机合成数据接口并通过 HTTP 测试，实际路径与范围以 backend/API_REFERENCE.md 为准；生产认证、真实邮箱和加密均未实现。

## 目标与边界

面向未来 Windows 客户端和 HUD 提供一致的待办、邮件、知识和审批操作；当前只允许使用合成数据。所有请求的 owner 由认证上下文决定，不从请求体或游标接受。Jarvis 资源要求 Jarvis 助手上下文；对陪伴助手的隔离必须在服务层再检查。摘要列表默认不返回正文、凭据或其他助手内容。

现有开发 token 和 Host/Origin 检查只是本机开发门禁；不能作为 Web 账户登录、用户在场证明或授予对外发送权限。任何把“confirmed_by_user”放进普通请求体的接口都不能单凭该字段作为生产授权。真实动作启用前必须实现可信交互、授权凭据、安全会话与独立安全评审。

## 典型审批状态与防重复

发送审批需要固定账号、收件人及抄送/密送、主题、正文、附件内容或不可变摘要、相关草稿版本、过期时间。任何相关内容变化、账户撤销、到期或拒绝都使旧批准失效。审批只允许一次使用；未来执行器在开始网络请求前记录唯一动作 ID，保存结果并防止并发双击重复执行。

网络超时不等于发送失败：若供应商不能提供可靠幂等或查询结果，状态应显示“结果未知，需检查”，不能自动重发；由用户检查后决定如何处理。仅同步读取或本地整理的批准不应扩大为对外沟通或删除授权。现有本地模拟服务没有任何对外执行能力，这里只是未来的验收要求。

## 数据与错误

- 列表默认有上限，返回摘要与下一页或明确截断标志；详情按需读取。日志只记事件类型、时间和非敏感标识，不记正文、令牌、模型请求内容或恢复材料。
- 服务返回稳定错误类别：未认证、无权访问、资源不存在、输入无效、状态冲突、依赖不可用；错误正文避免泄漏其他 owner 的存在及内部凭据。
- 状态变更与审计必须同一事务完成；同名资源跨连接不可混合。并发编辑、来源被删除、审批内容变化、撤销连接都应有自动化验证。
- 云模型调用前必须展示接收方和精确数据范围，并得到针对该请求的确认；邮件正文、附件或网页内容中的指令属于不可信数据，不能改变系统权限或直接触发工具。
