# 对话中枢需求补充：跨平台私信与持续聊天

**状态：** Proposed scope extension  
**版本：** 0.1  
**更新：** 2026-11-06

## 范围变化

用户希望 Jarvis 接管一个微信账号与 X 账号、搜索账号上的消息，并能通过微信与 Jarvis 聊天。这会把“内容收集”扩展为独立的**对话中枢（Message Hub）**：包含账号授权、会话索引、连续上下文、回复草稿、发送审批、撤权与审计。本阶段不连接真实账号。

## 需求依据

本项目关于连续性与双助手的产品方向仅依据用户主动分享的帖子和明确提出的想法，不使用媒体报道、学术论文或平台官方讨论作为用户需求数据。用户提出一个助手提供情绪价值、另一个是 Jarvis；首版微信聊天对象只设为 Jarvis。双助手与记忆边界见[双助手与连续性记忆设计](DUAL_ASSISTANT_DESIGN.md)。

## 首版能力建议

1. **Jarvis 对话入口：**用户可在 Jarvis 内持续对话；“通过专用微信号直接与 Jarvis 聊”需先验证平台允许的接入方式。
2. **本地会话搜索：**仅搜索已获准且成功导入的消息，按联系人、平台、日期和关键词筛选；结果显示来源与时间。索引在设备端解密后建立。
3. **记忆控制：**短期上下文按当前会话提供；长期记忆只从用户确认或明确开启的资料生成，可查看、编辑、忘记单项和清空。原始消息默认不自动成为长期记忆。
4. **理解与草稿：**摘要、待办/承诺提取、语气调整和回复建议；默认只保存草稿。
5. **外发审批：**向真实联系人发送消息、公开发帖/评论前，逐条展示账号、接收人/受众、完整内容和附件并由用户确认。确认只批准当前固定内容。
6. **接管控制台：**按平台管理读取、同步、代拟与发送权限；显示授权范围、最近同步、API 成本和异常；可立即暂停与撤销授权。

## “全部消息”的边界

目前不能承诺“查到所有消息”。历史时间范围、私聊/群聊、附件/语音、撤回或删除内容、平台保留期限都取决于官方接口、用户导出和授权范围。每个连接器须标示覆盖时间、会话类型、缺失项和同步游标。不得把账号密码、验证码、二维码登录态或 Cookie 交给 Jarvis；不读本地聊天数据库，不用私有 API、注入登录态或模拟点击抓取聊天。

## 平台接口判断

### 微信

本次公开资料检索没有确认个人微信账号读取完整私聊/群聊历史的官方开发接口。分享能力不等于读取聊天记录。首版可支持 Jarvis 内聊天，以及用户主动分享、复制/粘贴或导入；微信内直接与 Jarvis 对话是待验证项。若没有适用且获准的官方接口，就不把账号托管作为承诺。

### X

X 官方开发平台当前列出 DM Event Read 每条资源 $0.010、DM Interaction Create 每次请求 $0.015；价格与规则可能变更，实际可用范围要在开发者控制台验证。[X Developer Platform](https://developer.x.com/) 官方旧版文档说明了以用户上下文发送 DM 的接口，但这并不能证明可读取某账号全部私信历史。[X DM 发送文档](https://developer.x.com/en/docs/direct-messages/sending-and-receiving/api-reference/new-message)

在承诺接入前，必须实测 OAuth 权限、会话与事件范围、历史边界、分页、发送限制、费用和开发者条款。未验证前，X 私信仅是可选连接器，不进入首个交付承诺。

### 小红书

本次公开开放平台文档检索显示重点在商品、订单、库存等商业接入；未确认个人账号私信或收藏/点赞的开放接口。首版维持主动分享、复制/导入与网页剪藏。[开放平台简介](https://school.xiaohongshu.com/en/open/quick-start/introduction.html)

## 数据模型增补

- **ConnectedAccount：**平台、账号标识、授权范围、连接状态、同步时间、撤销时间、凭据引用（令牌仅进系统凭据库）。
- **Conversation：**所属账号、平台会话 ID、私聊/群聊/助手会话类型、参与者、覆盖时间范围、同步游标与状态。
- **Participant：**平台用户 ID、显示名、是否为本人、AI 参与披露状态。
- **Message：**会话、平台消息 ID、发送者、时间、加密正文、附件引用、方向、删除/导入状态。
- **ReplyDraft：**回复对象、加密正文、来源消息、模型来源、草稿/已批准/已发送/已拒绝状态、审批快照哈希。
- **DelegationPolicy：**账号、只读/仅草稿/逐条审批/受限自动模式、允许联系人/话题/时段、到期时间、启用时间。
- **MemoryItem：**加密内容、来源、全局/联系人/项目范围、用户确认时间、到期或遗忘时间。
- **ActionAuditEvent：**执行主体、动作、目标、载荷哈希、审批 ID、结果和时间。

群聊中其他参与者的消息也属于敏感数据；采取本地加密、最少留存和删除策略。消息内容不得出现在明文服务器日志或分析事件中。云模型调用前按既定隐私规则提示发送字段、接收方和目的。

## 权限与流程

1. 授权前展示读取的平台、会话类型、时间范围、模型数据去向、预计 API 费用和保留/删除方式，只申请当前功能需要的最小范围。
2. 导入后显示实际覆盖范围、缺失项和同步状态；“全部”拆成可验证的具体范围。
3. Jarvis 回复只使用当前会话及获准记忆；跨会话引用要显示来源时间。
4. 默认逐条生成草稿、逐条确认发送。撤回/删除、转账/交易、验证码及其他高影响动作永不自动执行。
5. 用户可暂停、撤销授权、清除连接器副本或删除 Jarvis 数据；多设备撤权须配合密钥轮换方案。
6. 未来若提出限定自动回复，必须另做范围决策；需按联系人/话题/时段白名单、对方可理解的 AI 披露、完整日志和随时停用，不能默默冒充用户。

## 路线图增补

- **M1：**Jarvis 自有对话面板，使用本地知识与待办；支持导出、清空和用户确认记忆。
- **M2：**对话数据模型与假数据，完成搜索、摘要、回复草稿和审批流程，不连外部消息账号。
- **M3：**验证 X API 可用范围、历史边界与费用，决定是否开展只读私信试验；书签/点赞连接器保持独立。
- **M4：**微信官方接入可行性研究；若无合规路径，只做主动分享收集，不开发模拟操控。
- **后续：**任何自动代聊都需新的明确范围决策，默认保留逐条确认。
