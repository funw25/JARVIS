# Jarvis 本地模型预览与建议 J4a

**状态：** 合成数据、本机模拟器，已验证；没有云端模型连接。

Jarvis 可以对同一用户的合成邮件或知识条目准备摘要/回复建议预览。预览包含用途、来源、提供方、本地接收位置、完整输入、是否离开设备、有效期和内容哈希。邮件摘要只选择主题和正文；回复建议额外选择发件人。当前提供方是进程内的 local_fake，输出显式标注“模拟，非 AI 生成”，不能作真实 AI 能力展示。

必须由用户确认当前哈希后才执行模拟；取消不会调用模拟器。来源变化、载荷被改动、到期或重复执行会拒绝；成功只生成可追溯的待处理建议，不创建待办、不发送邮件。请求取消、执行、失效或在后续访问时发现到期，会从当前记录清空预览载荷；SQLite 历史页/WAL 仍可能保留旧字节，这不是安全擦除。没有后台定时清理，真实资料禁入直到加密与保留策略实现。

知识条目修改或软删除会使相关待审预览失效并删除已有派生建议；建议读取也检查原条目仍可用。审计只记录动作及对象 ID，不记录输入正文。

未来真实模型需由用户显式配置；发送前逐次显示目的、接收方、完整必要内容并允许取消。不得将静态 API 令牌或原始邮箱全量暴露给模型；外部邮件/网页正文是待处理数据，不得改变工具权限或审批规则。外部传输、供应商隐私、超时与重试、数据保留、费用、输出结构验证和幂等必须另行实现与验证。

验证：backend/verification/verify_model_consent.py 覆盖预览/取消、用户确认、一次执行、owner 隔离、修改失效、载荷篡改、过期、审计正文隔离及无发送提案。

## J4b：用户确认后转成本地草稿

仅同一用户的邮件回复建议可转成合成草稿。调用方必须传入用户已确认的账号、收件人、主题和编辑后正文；创建草稿、标记建议已处理与建立关联在同一事务完成。重复或并发提交只能产生一个草稿；来源不存在或建议类型不符时整体回滚。创建草稿不产生发送提案，之后仍需单独预览并逐项批准；当前没有发送器。确认标志由受信任的内部调用方提供，未来接 UI/API 前仍需实现可靠的用户身份和最终内容确认。

验证脚本 backend/verification/verify_reply_draft.py 覆盖显式确认、owner 隔离、并发去重、无自动发送、单独审批、来源缺失回滚和审计。


## 模拟建议拒绝（2026-11-07）

Jarvis 合成建议可在用户明确确认后拒绝；仅未处理建议可拒绝，已转为草稿的建议不能反向撤销成未处理。拒绝会清空当前行的建议正文并记录不含正文的审计元数据。此为逻辑清理，无法保证物理擦除；仍只有本机假模型，没有真实 AI 或网络。验证见 `backend/verification/verify_model_consent.py`、`verify_reply_draft.py`。

2026-11-07：本机假模型预览、取消、确认、拒绝和转草稿已接合成 HTTP 路由并完成端到端测试；真实云模型仍未配置或调用。
