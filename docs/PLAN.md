## 1. 需求复核结论

### 1.1 一句话定义

Jarvis 是**本地优先的个人信息与行动中枢**，用电影 HUD 的工作台界面，把分散的邮件、收藏、资料和消息汇总成可理解、可执行、可追溯的个人工作流；其中包含两个身份清晰的助手（陪伴助手 / Jarvis），一切外部写操作逐项人工审批。

### 1.2 三条不可动摇的约束

| 约束 | 具体含义 | 违反时的可观察现象 |
|---|---|---|
| 建议与执行分离 | 模型只产出建议；写操作必须变成带载荷快照的待审批动作 | 界面上出现"已发送/已修改"而无审批记录 |
| 本地优先 + 端到端加密 | 正文与附件在客户端加密后才上云；服务端只见密文与路由元数据 | 服务端可做全文索引、日志出现正文 |
| 数据可追溯、可撤回 | 每条记忆/摘要/动作可回到来源；删除与撤权会清理索引与副本 | 删除后仍能被检索或续聊卡引用 |

### 1.3 交付切分（已确认）

- **增量 A（首版第一次交付）：** 双助手切换 + 独立会话 + 记忆分区 + 续聊卡 + 基础待办；全部本地假数据。
- **增量 B（首版第二次交付）：** 邮件 triage/草稿/规则整理/逐项审批发送 + 待办完整化 + 审计与恢复。
- 对话中枢（微信/X 私信）、语音、多设备同步、E2E 协议属于增量 A/B 之后的独立里程碑。

### 1.4 功能基线 v0.2（本文档锁定的实现口径）

| 编号 | 功能 | 首版深度 | 原型（本期） | 正式实现（M1+） |
|---|---|---|---|---|
| F0 | 统一收集箱 | 轻量 | 卡片列表 + 来源/捕获方式标签 + 手动粘贴 | SQLite `CaptureItem` + 快捷键/剪贴板 |
| F1 | 总览 | 完整 | 状态核心 + 四个派生指标 + 两侧信息舱 | 同构，指标全部从 store 派生 |
| F2 | 邮件 | 完整（模拟） | 搜索/筛选/摘要/草稿编辑/转待办 | Gmail 只读 → 草稿 → 审批发送 |
| F3 | X 收藏 | 轻量 | 搜索 + 来源/主题筛选 + 本地标签 | 官方 API 只读同步 |
| F4 | 知识库 | 轻量 | 笔记 CRUD + 搜索 + 提取待办 | FTS5 全文检索 |

## 3. 方案

### 3.1 目标形态：v0.3 原型信息架构（已实现）

```
┌───────────────────────────────────────────────────────────────────────┐
│ ⌁ JARVIS  助手[陪伴|Jarvis]   同步:本地  麦克风:未启用  待审:2  ⚙设置 │  系统栏
├──────────┬────────────────────────────────────────────────────────────┤
│ ⌂ 总览   │  页面标题 / 说明 / 模拟数据徽标                             │
│ ✦ 对话   │  ┌──────────────┬──────────────────┬────────────────┐        │
│ ✉ 邮件   │  │ 左侧信息舱   │   中央状态核心    │ 右侧信息舱     │        │
│ ♡ 收藏   │  │ 优先邮件     │  当前助手 + 负载  │ 今日任务       │        │
│ ▤ 知识   │  └──────────────┴──────────────────┴────────────────┘        │
│ ✓ 任务   │  ┌───────────────────────┬─────────────────────────┐        │
│ ◷ 审批 2 │  │ 收集/收藏/知识带        │ 审批队列                │        │
│ ❖ 记忆   │  └───────────────────────┴─────────────────────────┘        │
│ ＋ 收集  │  底部：HUD CONCEPT PREVIEW · SIMULATED ONLY                 │
└──────────┴────────────────────────────────────────────────────────────┘
```

- 导航固定 9 项：总览、对话、邮件、收藏、知识、任务、审批、记忆、收集；设置放在系统栏齿轮。
- 新增页面只复用既有 HUD token（角标、等宽字、青蓝/琥珀），不新增一套视觉语言。
- 每个页面顶部都有"模拟数据 / 未连接"徽标，避免误认为已接真实服务。

### 3.2 双助手切换模型

| 维度 | 陪伴助手 | Jarvis |
|---|---|---|
| 默认读取 | 陪伴记忆、自身会话 | 工作记忆、邮件/待办/知识、自身会话 |
| 工具 | 无外部工具；可"建议"创建待办 | 任务/知识/邮件连接器；写操作走审批 |
| 会话 | 独立 `conversation` | 独立 `conversation` |
| 切换行为 | 保留另一助手会话与草稿；不清空、不混入上下文 | 同 |

实现要点：`state.assistant` 为唯一身份来源；渲染时先按身份过滤记忆与工具入口；切换**不得**把 A 的历史自动注入 B（对应增量 A 第一条完成标准）。

### 3.3 本地数据模型（v0.3 已实现口径）

下表字段名与 `preview.html` 的 `seedData()` 一致，后端建表时沿用同一命名（正式版把 `ns` 展开为 `profile_shared / companion / work / conversation_raw`，把 `hash` 记为 `payload_hash`）。

```ts
type Assistant = 'companion' | 'jarvis';
type NamespaceId = 'shared' | 'companion' | 'work' | 'raw';

interface MemoryItem { id: string; ns: NamespaceId; cls: string; content: string;
  sources: string[]; confidence: number; approvedAt: string;
  visible: Assistant[];        // 可见助手：默认单边，共享条目为两边
  forgotten?: boolean;         // 禁记：保留记录但不再召回
  sharedFrom?: string; }       // 跨助手分享出的受限副本指向原条目

interface ContinuitySnapshot { id: string; assistant: Assistant;
  topics: string[]; open: string[]; status: 'draft'|'accepted'|'discarded'; createdAt: string; }

interface CaptureItem { id: string; sourceApp: string; method:
  'official_api'|'extension'|'share'|'clipboard_hotkey'|'file_import'|'manual';
  url: string; title: string; selectedText: string; scope: string;
  capturedAt: string; state: string; }

interface Todo { id: string; title: string; due: string;
  priority: '高'|'普通'|'低'; status: 'open'|'done';
  source: string; owner: Assistant; }

interface ActionProposal { id: string; kind: 'email_draft'|'local_tag'; title: string;
  payload: Record<string, unknown>; hash: string;   // 载荷哈希，变更即失效
  status: 'pending'|'approved'|'rejected'|'expired'|'executed'|'failed';
  createdAt: string; expiresAt: string; approvedAt?: string; executedAt?: string; }

interface AuditEvent { id: string; at: string; event: string; detail: string; }
```

### 3.4 关键流程（每条都要能在原型里点出来）

1. **记忆写入：** 会话结束 → 生成候选记忆（可见来源与置信度）→ 用户接受/改写/拒绝/禁记 → 写入对应 namespace + 审计。
2. **续聊：** 生成续聊卡草案 → 用户勾选保留项 → 新会话按话题召回少量条目，并标注"来源于某次对话"。
3. **审批：** 建议 → `ActionProposal`（含 `payloadHash`）→ 预览完整载荷 → 批准 → 执行前重算 hash，不一致则作废 → 模拟执行 → 审计。
4. **模型调用：** 首次与每次发送前显示「将发送的数据类别 / 接收方 / 是否包含工作资料」→ 用户取消则不产生请求 → 界面停留"已取消"。

### 3.5 工程结构（迁移路径，不一次性重写）

```
preview.html                # v0.3 仍保留单文件（双击可用）
frontend/                   # M1 起
  src/{app,views,components,store,selectors,seed,styles}
backend/                    # M1 起
  app/{main,routers,services,repos,models}
docs/                       # 本文与既有设计文档
```

拆分注意：改用 `<script type="module">` 后 `file://` 直开会被 CORS 拦住，**必须先确认原型验收方式**（见决策 D3）。因此 v0.3 阶段保持单文件，内部已经按"数据（`seedData`）→ 选择器（`memFor/pState/pendingProposals`）→ 视图（`*Page`）→ 事件（document 级委托）"四层组织，搬迁时逐层平移即可。

**P2 验收清单（增量 A 的原型对应项）**

1. 任一页面顶部都能看到当前助手，切换后对话页与记忆页内容随之切换。
2. 两个助手会话独立；切换不会把另一助手历史带入。
3. 记忆页列出每条记忆的类别、来源、时间、可见助手，默认不跨助手可见。
4. 记忆可创建、改写、纠错、禁记、删除、单条分享（分享前显示接收方与摘要）。
5. 续聊卡可生成、审阅、接受；新会话按卡召回并标注来源。
6. 删除记忆后，检索与续聊卡不再返回该内容。
7. 首次模型调用前出现发送提示，取消后无请求、界面显示已取消。
8. 全流程使用合成数据，页面无任何"已连接/已发送"表述。
