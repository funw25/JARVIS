# Jarvis 产品需求与范围

**状态：** Active baseline  
**版本：** 0.1  
**更新：** 2026-11-06

## 产品愿景

Jarvis 是一个可视化的个人 AI 工作台，帮助用户看清需要处理的信息、理解内容、把内容转成行动，并安全地完成日常整理。界面采用科幻电影 HUD 的空间感和信息密度，但所有数据与操作仍要容易读懂、容易控制。

**核心定位（已确认）：** 统一个人信息与行动中枢，把分散的邮件、收藏、知识和任务汇总为可理解、可执行、可追溯的个人工作流。

**当前阶段交付（已确认）：** 完善需求/架构文档、可交互 HUD 原型和分阶段开发路线图；此阶段不连接真实账户。

## 目标用户与主要场景

首要用户是个人知识工作者和开发者；第一位用户是熟悉 Python/C++、前端经验有限、希望自己逐步实现系统的个人开发者。

主要场景：

1. 早晨打开 Jarvis，快速知道哪些邮件值得优先处理、今天有哪些待办。
2. 阅读收藏和点赞的帖子，将有价值内容打标签、写摘要或转成待办。
3. 把本地文档、手写笔记和邮件沉淀进个人知识库，并按来源检索。
4. 检查 AI 的建议；发送、删除或发布之前，准确看到将要执行的内容并明确确认。

**当前优先级更新（2026-11-06）：** 先完成 Jarvis 的信息处理与行动能力。陪伴模式保留独立通道和已有数据结构，暂停扩展，其具体需求由用户之后重新梳理。

## MVP 功能优先级

| 能力 | 首版深度 | 第一阶段定义 |
|---|---|---|
| 邮件 | 完整主流程 | 收件箱 triage、摘要、搜索、规则化整理、回复草稿、审批发送 |
| 待办 | 完整主流程 | 创建/编辑/完成/优先级/截止时间、来源关联、规则化提醒 |
| X 收藏与点赞 | 轻量入口 | 连接状态、导入/浏览、基础筛选；高级语义整理后续做 |
| 知识库 | 轻量入口 | 手动收集、基础标签与搜索；自动知识图谱/深度问答后续做 |
| 跨应用收集 | 统一入口 | 微信、X、浏览器、小红书、邮件和其他应用；按来源使用 API、浏览器剪藏或用户主动分享/粘贴 |

“轻量入口”的细节仍待验证：暂按可以收集、查看和做基础整理处理，不承诺首版完整 AI 管理体验。

## MVP 目标

- 一个首页可以概览邮件、待办、收藏、知识与待审批操作。
- 邮件可筛选、总结、生成回复草稿；可按用户规则执行可逆整理；发送需逐项确认。
- 待办可建立、编辑、完成、设优先级/截止时间，并关联邮件或资料。
- X 书签与点赞、知识库提供轻量收集、浏览和基础查找入口。
- 提供统一收集入口，把来源、URL、时间和用户选中的内容保存为待整理项。
- 高影响操作经过明确、逐项、可审计的人工审批。
- 通过按键启动语音输入；Jarvis 可以语音播报回复；不常驻监听。
- 目标是跨设备使用，提供 Windows 桌面体验和网页登录；内容本地保留并通过端到端加密同步，密钥恢复/设备撤销协议仍待设计。

## 功能需求

### F0 统一收集箱

- 支持从浏览器、微信、小红书、X、邮件及其他应用收集用户明确选择的内容。
- 每条收集项保留来源类型、来源链接、捕获时间和捕获方式；无法解析来源时允许手动补充。
- 首版优先实现通用剪贴板/粘贴、URL 保存、文件拖放和浏览器剪藏；官方 API 连接器按平台权限逐个增加。
- 第三方应用没有合规个人数据 API 时，必须提供用户主动分享/复制/导入方式；不读私有数据库、不注入登录态、不用账号密码或 Cookie 抓取。
- 收集项可保存在本地，稍后归档到知识库或转为待办。

### F1 总览

- 展示连接状态、同步时间、待处理邮件数、未完成待办数和待审批数。
- 中央 HUD 核心表示当前助手状态；它不得暗示 Jarvis 正在监听麦克风或自动执行任务。
- 邮件、内容与待办摘要都能跳转到对应模块及其原始来源。

### F2 邮件

- 邮件列表支持搜索、未读/需回复/重要等筛选。
- AI 提供简短摘要、建议优先级和“建议回复”草稿。
- 草稿可修改、复制或保存为 Gmail 草稿（后续授权功能）。
- 发送前显示完整收件人、抄送、主题和正文，用户逐封确认。
- 用户可配置规则对标签、归档等可逆整理动作进行自动执行；每条规则可预览、暂停和撤销。
- 移入垃圾桶需要显式确认；MVP 不实现永久删除或批量删除。

### F3 X 收藏与点赞

- 只读取用户本人可访问的书签和点赞帖文。
- 支持本地标签、主题筛选、搜索、摘要和待办转换。
- 本地整理不改变 X 状态。取消收藏、取消点赞、发帖不属于首发范围。
- 显示同步时间及 API 费用/读取量提示；手动同步优先于后台轮询。
- 首版为轻量入口：先验证收集/浏览/基础整理，不承诺大规模自动回顾或语义分类。

### F4 知识库

- 支持手动笔记、Markdown、TXT，之后再增加 PDF 等格式。
- 知识条目保存标题、正文、标签、时间、来源和来源链接。
- MVP 用本地全文搜索；数据量和需求明确后再增加向量检索。
- 首版为轻量入口：先支持收集、基础标签和搜索，复杂知识问答后续评估。

### F5 待办

- 支持标题、说明、状态、优先级、截止时间和来源引用。
- 支持从邮件、X 内容和知识条目创建任务。
- 完成、修改、延期等是 Jarvis 内部动作，不需要外部服务授权。
- 可以基于用户配置的规则创建/安排待办；规则必须可查看、暂停和回滚。

### F6 审批与记录

- 写操作必须先形成待审批动作，LLM 不能直接调用写接口。
- 审批对象应绑定动作类型、目标 ID 和完整动作载荷；载荷变化后旧批准失效。
- 明确区分批准、拒绝、过期、执行成功和失败。
- 外部操作记入本地审计记录，并提供撤销授权和断开连接入口。

## 非目标

- 复制电影、参考仓库中的专有图形、代码、音乐或品牌元素。
- 持续摄像头、手势追踪、卫星地图、环境监控或常驻语音监听。
- 自动发送、永久删除、清空邮箱、自动发帖或自动取消 X 收藏/点赞。
- 多用户协作、组织管理、移动端完整体验、复杂 Agent 编排。
- 绕过平台官方授权限制，抓取第三方应用的私有接口、账号 Cookie 或聊天数据库。
- 初版就引入多个微服务、Kubernetes、复杂事件总线或自建模型训练。

## 非功能需求

- **安全：** 最小 OAuth scope；令牌不进浏览器 localStorage、不写日志、不提交版本库。
- **隐私：** 本地优先；跨设备同步端到端加密，云端仅保存密文；云模型调用前解释发送字段、目的与接收方；支持删除本地数据和撤销连接。
- **可追溯：** 每个摘要和分类可回到原始来源；AI 生成内容标注为建议。
- **可恢复：** 本地数据库可备份、导出；同步失败不覆盖已有内容。
- **性能：** 首页本地渲染目标 2 秒内；大量数据通过分页/增量同步处理。
- **可访问性：** 支持缩减动态效果、清晰文字层级、键盘操作与高对比度。
- **可靠性：** 外部 API 错误、令牌过期、超限和离线状态有清楚反馈，不假装成功。

## 已确认的版本范围

- **完整主流程：** 邮件 triage/总结/草稿/规则化整理/审批发送；待办 CRUD、优先级、截止时间、来源关联。
- **轻量入口：** X 收藏/点赞和知识库先支持收集、浏览、基础整理/查找；完整智能整理放在后续版本。轻量入口的准确边界仍需通过原型确认。
- **平台：** Windows 桌面体验 + Jarvis 网站登录，多设备使用。暂按两个客户端登录同一 Jarvis 账户理解。
- **收集来源：** 微信、X、浏览器、小红书、邮件和其他应用；优先 API/分享/剪藏/粘贴等用户主动路径，不默认后台抓取。
- **同步：** 本地优先，端到端加密后同步；云端只持有内容密文和最低限度账户/路由元数据。密钥恢复、设备撤销和冲突合并机制仍需设计。
- **语音：** 首版按键启动输入与语音播报；没有常驻监听。语音识别/合成服务、是否本地处理待定。
- **视觉：** 实用型电影 HUD，中央状态核心、环绕信息舱、青蓝与琥珀光效。
- **自动化：** 用户可配置规则自动执行可逆整理动作；对外沟通始终逐项确认；删除与高影响动作也要单独确认。
- **当前交付：** 需求/架构文档、可交互 HUD 原型、分阶段开发路线图。

## 新增范围提案：对话中枢

用户提出管理微信和 X 消息、搜索历史并通过微信与 Jarvis 聊天。此需求超出原先“内容收集”，应按独立对话中枢规划。完整需求、调研依据、数据模型、审批和平台限制见[对话中枢需求补充](MESSAGE_HUB_REQUIREMENTS.md)。

- Jarvis 内持续聊天、获准消息搜索、上下文/记忆控制和回复草稿进入后续设计。
- “搜索全部消息”和“微信直接聊天”均须先验证平台接口及可授权范围，当前不作完整覆盖承诺。
- 所有向真实联系人发送的消息仍逐项确认；当前不连接真实账号，不接受账号密码、验证码或 Cookie。

## 新增产品方向：陪伴助手与 Jarvis 双助手

用户提出将产品分成两个 AI 助手：一个提供情绪价值，一个负责 Jarvis 的信息与行动管理。建议共享本地优先的个人记忆底座，但按助手分区授权；人格、会话和工具权限清晰区分。连续性要求不限于摘要记忆，还包括重要经历、未完话题和可追溯的记忆来源。具体设计见[双助手与连续性记忆设计](DUAL_ASSISTANT_DESIGN.md)。
