# 代码治理第二批（2026-11-14）

## 改动与边界

1. `verification/test_environment.py` 为整套回归建立子进程环境，移除继承的 `JARVIS_*`；`verify_all.py --experimental-apswmc` 显式启用实验适配器并生成新测试密钥，`verify_adapter_suite.py` 使用该入口。测试可自行切换后端，因此不能声称每一项都在加密库上执行。这个隔离仅覆盖整套回归启动的子进程，不自动保护直接运行的其他脚本，也不替代生产端不可变配置。
2. 备份编排与保留、审计拆分到 `backup_job.py`、`backup_retention.py`、`backup_audit.py`，原 `backup_job.audit` 和保留函数仍可调用。任务的本地及远端保留数量必须是正整数，且在访问凭据或创建文件前验证；直接清理函数允许 0（用于明确清空或测试锁定对象），但拒绝负数和非整数。审计仍是明文追加，没有完整性保护，不能用于真实资料安全声明。
3. M1 报告保留原 JSON 格式及旧字段，以 `details` 为逐样本事实来源，提供 `evaluation_issues(report)` 读取分类、todo、draft、priority 差异和不受支持的证据。`missing_evidence` 仅表示空证据；`evidence_unsupported` 还包括非空但无法在来源中核对的证据。该接口按已有报告内容计算，不新增模型调用或宣称质量提升。
