# Jarvis 代码治理计划（2026-11-14）

目标：保持现有虚构数据行为和安全门槛，使模块边界、验证结果和后续 Agent 开发易于理解。优先消除会掩盖失败或影响数据安全的问题；每一步先确定调用方及合同，再迁移与验证。真实资料仍禁止，G1 仍未批准。

## 顺序与决策

1. **验证可信度和卫生（R1–R3、L3–L4）：进行中。** 已分别报告功能回归与供应链诊断；16 个验证脚本停止忽略临时目录清理错误，定位并修复 SQLite 连接及迁移早退泄漏，删除 19 个已核对的测试残留。没有添加会掩盖残留的宽泛忽略规则。公共验证工具和环境配置隔离仍待做。
2. **接口与领域边界（C1、L2）：进行中。** API 已按原注册顺序拆成 7 个模块，55 条路由及 OpenAPI 与重构前一致。service 是领域能力，usecase 是跨服务流程的方向需进一步对照现有模块落实；不能仅凭名字机械迁移。
3. **控制流与报告（C4–C6、L5–L6）：进行中。** 邮件规则将整批源数据核对和修改收敛到独立步骤，仍在同一事务内，失效状态先提交再抛错；概览提取日期分桶；G1 将评审材料核验从文件检查分出。评测报告和备份编排仍待做。
4. **安全存储（C2–C3、C7、L1）：待设计与验证。** 不因代码行数删除手写适配器或密钥逻辑；先固定事务、并发、游标生命周期、崩溃恢复合同，评估直接 APSW 接口与显式配置注入的迁移成本，逐步替代。保留真实数据与发布门禁。
5. **实验代码与工具收敛（R4–R9）：先建立引用和覆盖矩阵。** 旧 vault/探针、Ollama 启动脚本、Streamlit 原型、合成服务各有历史或实验作用，不能仅凭主应用无引用断定可删；确认验证覆盖、入口与迁移说明后再归档或删除。公共函数仅在语义一致时抽取。
6. **文档治理（R10）：** CURRENT_STATUS 为现状入口，PROJECT_LOG 为按时间追加的事实，M1 报告和 CHECKPOINT 保留为带日期的历史证据，路线图只记录计划；数字尽量自动生成或链接来源，历史数字不冒充现状。

## 首批引用核对

- 两个旧 vault 当前分别支持 SQLCipher 实验和 APSW 的初始化/崩溃探针；并非主应用当前 vault 的等价副本。下一步先把独有故障场景迁入对应合同测试，再移除候选实现。
- `synthetic_mail_sync_service` 被虚构同步和邮件会话测试使用；另外两个合成服务各有专项测试。它们没有主应用入口并不等于不再有用，应先决定是否保留为实验模块、迁移测试边界，再删除或移动。
- Ollama 的 `ollama_in_project.py` 是隔离环境启动器；`start_ollama.ps1` 是后台启动、`serve_ollama.ps1` 是前台启动、`setup_local_model.ps1` 负责准备并调用启动，`bootstrap_ollama.py` 获取并校验发行文件。它们不是四套完全独立实现；后续可收敛公共配置，但须保留前台、后台与离线防云合同。
- 当前 `services` 包含业务状态和事务能力；`usecases` 包含 M1 建议、评测与流程。应以依赖方向和职责而非目录名判断迁移，不能让模型直接绕过审批或存储门禁。

## 验收原则

- 不访问真实账户、真实数据或外部服务；实验仅用虚构材料。
- 功能专项、完整合成回归分别记录；诊断成功不等于 G1 批准，SKIP 不等于通过。
- 不把需要第二台机器、独立评审或观察期的事项标为已完成。
- 保留历史结果真实性；记录未处理项、兼容性变化与风险。
