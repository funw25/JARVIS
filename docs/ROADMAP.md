## 原双助手交付切分（历史记录，顺序已由上方更新）

此前讨论过双助手与邮件/待办分两次交付。用户现已决定先做 Jarvis，陪伴方向暂缓；下面保留原验收设想，作为将来重新讨论时的参考。

### 增量 A — 双助手与连续性基础

**交付：** HUD 中可切换陪伴助手与 Jarvis；各自拥有独立会话与权限；本地记忆分区、用户可审阅的续聊卡、记忆来源/编辑/删除；Jarvis 提供基础待办列表。  
**范围：** 本地数据和模拟对话为主，不连接微信/X/Gmail；不做对外代聊；不承诺模型跨版本保持完全相同的人格表现。  
**完成标准：**

- HUD 始终显示当前助手；两助手会话独立，切换身份不会把前一助手的历史自动带入。
- 记忆页能列出每条记忆的类别、来源、创建时间和可见助手；默认拒绝跨助手访问。
- 创建、编辑、纠错、禁记、删除和单条分享都能完成；分享前显示接收助手、摘要内容和来源。
- 创建续聊卡后可在新会话恢复用户批准的内容；未经确认的候选记忆不会长期保存。
- 删除某条记忆后，相关检索索引与续聊卡不再返回该内容；未同步设备显示待处理状态。
- 云模型调用前显示发送内容类别和模型接收方；用户可以取消，取消后不发出请求。
- 使用合成/本地资料完成演示；无真实社交、邮件账号连接。

### 增量 B — Jarvis 工作流完整化

**交付：** 完整待办管理；Gmail 连接后的邮件 triage、摘要、搜索、规则化整理、回复草稿与逐项审批发送；审计和恢复流程。  
**范围：** Gmail 先只读验证，再单独启用草稿/整理写权限和逐条批准的发送；陪伴助手默认不读取邮件或待办内容，用户可选择分享单条摘要。  
**完成标准：**

- 待办可创建、编辑、设状态/优先级/截止时间、完成/重开，并关联邮件或资料来源。
- Gmail 邮件可筛选、摘要和搜索；回复草稿可编辑；规则整理需预览且可撤销。
- 发送前逐项展示 Gmail 账号、收件人、主题、正文与附件；只有确认当前未变化的草稿才能发送。
- 撤销 Gmail 授权后停止同步并提供清理本地副本选项；同步错误不覆盖上次成功数据。
- 陪伴助手无法检索邮件和工作资料；只有用户明确分享的单条摘要才进入陪伴命名空间。
- 每次外部写操作有结果记录；日志不包含完整正文或凭据。

上述是分批交付建议；开发前仍需完成 P0 需求基线和 P1 架构审查。

## M0 — HUD 视觉验证（已完成；当前冻结）

**交付：** `preview.html` 全屏 HUD 概念原型、视觉规范。  
**范围：** 假数据、模块导航、概览、中心状态核心、待办勾选、收藏卡片、审批演示。  
**验收：** 首屏体现 Jarvis HUD；状态含义清楚；无外部连接；遵守 reduced-motion。

## M1 — 本地核心工作流（后端领域与 /api/v1 已编码；运行验证与安全加固待做）

**交付：** React/Vite UI、FastAPI 客户端服务、SQLite 数据模型、Capture Inbox、搜索、知识条目、任务 CRUD、来源关联。  
**范围：** 不需要 OAuth；支持手动粘贴、URL、剪贴板、文件导入；提供 Windows 全局快捷键原型；数据先本地保存。  
**验收：** 重启后数据仍在；捕获项有来源和时间；笔记和待办可搜索；任务可回到来源。

## M1.5 — 账户、设备与端到端加密同步

**交付：** Jarvis 账户、设备关系、端到端加密同步协议、密钥恢复/轮换/撤销方案、离线冲突策略。  
**范围：** 服务端仅存密文和最低限度同步元数据；不接真实邮件/X；先用本地合成数据验证多设备恢复。  
**验收：** Windows 与 Web 客户端均可登录同一账户；服务端无法解密测试正文；丢失/撤销设备、恢复密钥和删除账户的行为已明确定义。

## M2 — AI 辅助整理

**交付：** 模型提供方接口、摘要/分类/待办提取、来源引用、成本与错误状态。  
**范围：** 用户先配置模型；LLM 无工具执行权限；结果必须可编辑/拒绝。  
**验收：** AI 输出作为建议保存；每条输出能追踪来源；离线/超时有明确状态。

## M2.5 — 按键启动语音

**交付：** 按键启动录音、文本确认、中文播报与打断控制。  
**范围：** 无常驻监听；ASR/TTS 提供方和是否本地处理待选；云处理前说明音频/文本去向。  
**验收：** 麦克风状态清楚；用户能取消与删除语音内容；播报不阻塞普通键盘/鼠标操作。

## M2.7 — 浏览器剪藏与分享入口

**交付：** Chrome/Edge 剪藏入口；Windows 快捷键捕获；微信/小红书用户主动复制或分享路径说明。  
**范围：** 仅保存用户选择的 URL、标题、选中文字或明确提交的文件；不读取私有聊天、页面登录令牌或账号数据库。  
**验收：** 每条收集项显示来源与捕获范围；无法读取网页正文时仍保存链接与用户选中的文本。

## M3 — Gmail 只读

**交付：** OAuth、邮件同步、列表/搜索/摘要、Jarvis 内回复草稿。  
**范围：** 只读 scopes；同步手动触发；不写 Gmail。  
**验收：** 连接、撤销、过期、分页、去重、错误恢复均有清楚反馈；令牌不暴露在前端或日志。

## M4 — X 只读

**交付：** 用户授权、本人书签和点赞导入、分页、搜索、Jarvis 本地标签。  
**范围：** 同步前提示用量与费用区间；由用户手动启动。  
**验收：** 只读、不改 X 状态；同步成本可观察；超限与 API 不可用时保留本地数据。

## M5 — 受控写操作

**交付：** 规则引擎、可逆整理自动化、审批服务、不可变动作快照、审计事件、Gmail 草稿保存。  
**范围：** 规则仅针对用户显式开启的低风险、可逆动作；外部沟通逐项批准；删除和永久删除仍关闭/严格确认。  
**验收：** 规则可预览目标、暂停与撤销；每次批准精确对应内容；改动后旧批准作废；重复点击不会重复执行；结果可审计。

## M6 — 长期扩展

候选能力：完整 X/知识管理、更多文件类型、向量检索、端到端加密多设备同步、Windows 桌面封装、其他任务/知识服务连接器。每项进入开发前先补充需求、隐私影响、费用和维护成本评估。
