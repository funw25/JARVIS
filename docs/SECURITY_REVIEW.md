# Jarvis 安全边界与开放问题

状态：开发阶段自查，不是独立安全审计；2026-11-06。当前只可使用合成资料，不能连接真实账号。

## 资产与信任关系

资产包括邮件及草稿、待办、知识、聊天、模型请求、OAuth 令牌、设备密钥和恢复材料。用户选择的来源正文、附件、网页和模型输出都应当视为不可信内容；它们可以提供信息，不应改变系统指令、授权范围、连接目标或执行动作。

当前本机服务假设调用者在同一设备，通过环境变量配置的开发 token 区分调用；这个 token 和监听地址不是登录系统，也不能抵御同一用户权限下的恶意程序。Windows 桌面客户端、未来 Web 客户端、同步服务器、外部账户提供方和用户选择的模型提供方是不同信任域。

## 可用保障与限度

本地领域服务检查 owner 与助手范围，规则操作使用预览与确认，邮件草稿改动会使审批失效，待办并发写入和授权撤销有合成数据测试。迁移版本和内容使用校验和，不能防止攻击者同时修改代码和数据库。独立演示使用临时虚构数据并在退出时清理，但清理不等于安全擦除。

合成数据验证只说明所测路径在当次环境下符合预期，不证明应用能够安全处理真实个人资料。任何外部连接需用户明确授权；发送、删除、发帖等动作需逐项展示并确认，当前均不可执行。

## 后续评审顺序

1. 扩展已通过的实际 HTTP 合成测试，覆盖更多路由、错误和重启；不要将路由导入当作 HTTP 测试。
2. 评估并验证加密存储、DPAPI 或替代系统安全存储，设计与测试恢复、备份、故障及迁移；审计前继续封闭真实资料。
3. 确认桌面与 Web 的信任、身份和客户端完整性，再评审同步协议和密钥生命周期。
4. 提前单独评估模型数据最小化与提示注入；真实 Gmail 先只读、用户明确连接，再逐能力批准额外权限。

2026-11-07 补充：本机 HTTP 现覆盖模拟邮件、知识、待办、提醒、规则及假模型的多项路径；不是所有路由或生产身份认证的验收。输入校验错误不回显提交值，开发令牌和助手选择仍不能证明真实用户在场。
