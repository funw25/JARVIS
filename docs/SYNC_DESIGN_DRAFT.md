# 多设备密文同步设计草案

状态：需求与验收草案，未选择协议/库，未实现。当前项目仅允许合成数据。2026-11-06。

## 目标与边界

用户在自己的 Windows 桌面和 Web 上使用 Jarvis；每个已授权设备能离线读取本地已有资料，在重新连接后同步。同步服务只保存密文和必要路由、版本、大小、时间等元数据；服务端不拥有可用于读取正文的密钥。邮件等来源仍各自受供应商权限约束；它们不是因同步而自动获得访问授权。

端到端加密不隐藏连接时间、设备数、密文大小和服务端路由信息；不保护已解锁设备被恶意程序控制，也不能阻止服务器不转发、延迟或删除密文。浏览器若从被攻击的服务器加载恶意 JavaScript，密钥与解锁内容可能泄露；部署和客户端完整性是额外安全边界。

## 建议数据与设备状态

- 用户账号用于登录同步服务，不等于邮箱/X OAuth 账号。设备登记、用户可识别的设备名称和授权状态应可审阅，设备 ID 不直接包含个人信息。
- 条目、版本、来源关联、软删除墓碑均在客户端形成经认证的密文对象；服务端保留最小同步所需索引。不同类型/用户/密钥版本不能发生跨域替换。密文格式、对象关联和元数据泄露需由所选成熟方案明确。
- 设备内的资料密钥由经审查的系统安全存储包装；恢复材料独立于设备保管。登录密码不应自动等同于数据恢复材料。密钥生成、包装、派生和认证算法必须选用成熟库和安全审查，不能自行设计密码学协议。
- 首台设备初始化后，新增设备须通过已授权设备或经设计的恢复流程确认；确认画面要让用户识别新设备。具体扫码、配对码、恢复材料格式与轮换流程待确定，不能把短信/账号登录单独视为已完成端到端设备认证。

## 同步与冲突语义草案

1. 本地变更先在同一事务中持久化对象版本及待同步队列，成功后可离线使用；客户端上传前完成加密。失败重试不能重复创建对象。
2. 新设备先验证设备授权和必要的密钥版本，再拉取并验证密文；先处理撤权与删除状态，再向用户展示可用数据。此要求不能单凭不可信服务器的承诺完成，反回滚与漏发检测须单独设计。
3. 两设备并发编辑同一条待办/笔记时，保留双方版本并提示冲突；不按服务器到达顺序悄悄覆盖。编辑不同字段是否自动合并、哪些字段不可自动合并，需针对每类对象定规则及测试。
4. 删除使用可同步墓碑，而非仅靠服务器物理删除。对已删除对象的离线旧版本不得自动复活；如果离线设备有未上传编辑，应放入隔离的冲突恢复区，用户决定是否另存新对象。墓碑保留、设备失联和垃圾回收策略尚未决定。
5. 撤销设备后阻止它获得后续密钥并轮换受影响密钥；旧设备已经复制的明文或旧密钥无法远程收回。新加入、撤销、轮换、设备长期离线及恢复后的冲突需要事务边界和故障恢复设计。
6. 云模型处理是独立数据流：只有用户针对具体请求确认后，客户端才向指定提供方发送必要明文；云模型服务和同步服务不是同一个信任域。

## 待评估方案

先比较可维护的本地同步/冲突库与现成端到端加密组件的许可、Windows + Web 支持、密钥/设备撤销、恢复、可信构建、测试能力和项目复杂度；CRDT 只解决一类合并问题，不自动提供端到端加密、授权、删除策略或可靠恢复。禁止因为“可以同步”就宣称隐私目标已满足。离线优先的单人版本可先不启用服务端，数据模型需保留后续演进空间。

## 合成数据验收矩阵

- 两设备离线创建、编辑不同条目、重复上传、断网重试、重启续传；最终无重复，服务端检查不到已知正文。
- 同一条目并发修改、修改与删除冲突、离线设备回归；保留冲突并阻止无确认复活。
- 新设备加入被拒绝、批准、失效；撤销设备并轮换后不得解密新内容，旧副本不可远程收回。
- 已授权设备丢失、恢复材料正确/错误/丢失、损坏密文、错误密钥和中断恢复；错误状态明确且不得退回明文。
- 回放旧包、遗漏删除、伪造元数据、篡改密文、密钥版本不匹配；协议需要提供可证明的检测能力或明确披露做不到的部分。
- 浏览器站点更新、脚本供应链、设备本地存储被清理、备份恢复和时钟偏差；测试结果必须区分功能正确性与安全审查。

## 决策门

选择同步部署方式和成本预算、设备上限、恢复材料体验、版本冲突交互、离线设备留存上限、附件大小、浏览器信任与发布机制后再编码。安全设计/威胁模型评审、密钥与恢复测试通过前，不上传真实个人数据。
