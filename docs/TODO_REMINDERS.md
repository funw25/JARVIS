# 待办本地提醒规则设计

状态：本机合成服务和 HTTP 接口已实现并通过验证；仅虚构数据，本机手动查询，无系统通知或后台调度。2026-11-07。

- 用户为一条有截止时间的 Jarvis 待办创建规则，指定提前 0 到 10080 分钟；创建时明确确认，规则可停用和重新启用。
- 查询时只返回已到触发时间、仍未完成且未删除的任务；过期未确认的提醒仍可查看。返回标题、截止时间和触发时间，不返回任务描述。
- 用户确认提醒后记录该次出现，重复确认不产生重复记录；同一截止时间若修改后又改回，使用新的日程版本，不会误把旧提醒当作新提醒已确认。
- 截止时间变化、完成后重新打开、删除后恢复会改变日程版本；规则重新启用改变规则版本。旧的待确认快照不能确认新的日程。
- 同步、跨设备去重、重复周期、推送、操作系统通知、后台服务和错过提醒的保留策略尚未实现。确认代表本地记录用户处理，不承诺系统已经展示通知。
- 关联、计算和确认只处理合成数据，不联网、不读取真实账户；实际产品需要加密与可信会话。

## 验证与接口

backend/verification/verify_reminders.py 使用临时虚构数据库验证隔离、触发边界、并发重复确认、过期快照、任务状态变化及触发时间排序。verify_http.py 用本地实际 HTTP 进程验证创建、查询、确认、过期拒绝和开关。API 调用模拟用户意图；开发令牌不能证明用户在场。确认快照散列仅用于发现内容变化，不是身份凭证。每次查询最多返回 100 条，超过 10000 条活动规则会拒绝查询，后续需设计分页和容量治理。
