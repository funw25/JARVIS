# 可信水位与签名密钥恢复：本地研究原型

## 完成范围

- `compare_with_pinned_history` 接受调用方独立提供的 checkpoint 摘要和公钥，验证完整同 epoch 签名历史与本地前缀；缺失摘要、历史不包含摘要或来源不可信时，不声称已获最新水位。即便签名链包含提供的 pin，函数仍返回 `ANCHOR_STALE_OR_UNKNOWN`，因为本地代码无法证明提供的 pin 或历史是最新的。
- `checkpoint_key_recovery.py` 提供**内存中**的签名私钥加密打包与恢复原型，使用固定 Argon2id 参数和 AES-GCM，将格式、KDF、salt、nonce 和公钥纳入认证；恢复必须由调用者另外提供独立可信的预期公钥。未创建用户密钥、凭据、文件或远端对象。错误口令、篡改、不同公钥和无效 KDF 被拒绝。
- 虚构密钥可在全新 Python 进程中由加密包、口令及独立给定的公钥恢复并验签；这是**同一台机器的进程隔离演练**，不是异机恢复，也未验证实际离线保存、找回、密钥轮换或撤销。
- M1 临时演示现在拒绝继承 vault/加密适配器，恢复进程原有数据目录变量，并在清理失败时失败；测试覆盖冲突拒绝、正常运行及临时目录清理。

## 不能宣称的安全能力

1. 备份包本身不能证明内含公钥可信；若包和预期公钥来自同一可替换来源，攻击者可以一起替换。尚无独立公钥信任根、可信新鲜度服务或不可回滚的水位持久化。
2. 恢复口令仅执行长度及编码检查，长度不能保证熵；加密包允许攻击者离线猜测口令。口令必须与备份口令独立，实际口令生成、保管和交互尚未实现。
3. Python 和底层加密库可能保留私钥及口令的内存副本；本原型不能保证清零、阻止恶意本机进程、保护页面文件或剪贴板。固定 KDF 参数是实验选择，不等于经过实际设备性能评估的正式策略。
4. 未实现真实密钥存储、变更/吊销、可信设备注册、多设备同步、outbox 派发和 epoch 转换。现有备份 `audit.log` 仍是明文；该原型不放行真实资料。

## 下一步

先建立可审查的威胁模型与恢复交互，设计独立可信公钥/水位的创建、持久化、遗失处理、签名密钥变更以及外部 witness 防回滚协议；再用两套隔离环境模拟旧水位、回滚和重放，最后由独立评审与异机演练验证。真实账户连接或 R2 部署需用户单独授权。
